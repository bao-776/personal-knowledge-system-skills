# Workflow router

| Intent | Route |
|---|---|
| Create or reorganize a vault | vault-bootstrap |
| Process new material | knowledge-intake |
| Find existing knowledge or answer from notes | knowledge-retrieve |
| Trace a changed conclusion | knowledge-impact |
| Prioritize a source batch | knowledge-triage |
| Audit vault health read-only | knowledge-health |
| Capture one selected item | knowledge-capture |
| Make durable notes | atomic-notes |
| Use Obsidian features | obsidian-vault |
| Plan learning or capability growth | growth-system |
| Capture a transferable insight | inspire-time |
| Track or resume a project | project-lifecycle |
| Review a project or period | retrospective |
| Understand recurring personal patterns | self-observation |
| Produce an audience-specific artifact | knowledge-output |

Route only to installed modules. Missing modules require a named limitation and bounded preview, not automatic full-suite installation. Lightweight and growth profiles may use this entrypoint.

Pass between stages: user goal, original-source locators, selected verification results, authorized paths and operations, existing conventions, completed writes, unresolved claims, and completion criteria. Do not duplicate preserved source content at every stage.

When several intents are present, choose the smallest sequence that reaches the requested outcome. Do not run optional downstream workflows automatically.
